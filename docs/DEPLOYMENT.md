# Deployment

ARANYA ships as three free-tier pieces:

| Piece    | Host                  | What runs there                                  |
| -------- | --------------------- | ------------------------------------------------ |
| Web      | Vercel                | The static SPA from `web/dist`                   |
| API      | Render (Docker, free) | `server/` built by `server/Dockerfile`           |
| Database | Neon (Postgres, free) | Schema from `server/drizzle`, data from the seed |

Vercel rewrites `/api/*` to the Render service, so the browser only ever talks to
one origin. That keeps the refresh cookie `SameSite=Lax`, the CSP at
`connect-src 'self'`, and CORS out of the picture for real users.

```
browser ──► vercel.app ──/api/*──► aranya-api.onrender.com ──► Neon
              │
              └── everything else ──► index.html (SPA fallback)
```

## 1. Neon (database)

1. Create a project at <https://console.neon.tech> (region close to your Render region).
2. Create a database named `aranya`.
3. Copy the **pooled** connection string. It looks like
   `postgresql://USER:PASSWORD@ep-xxxx-pooler.REGION.aws.neon.tech/aranya?sslmode=require`.
4. Load the schema and catalogue once, from your machine:

   ```bash
   DATABASE_URL='<neon pooled url>' npm run db:migrate
   DATABASE_URL='<neon pooled url>' SEED_ADMIN_EMAIL='you@yourdomain' \
     SEED_ADMIN_PASSWORD='<a long unique password>' npm run db:seed
   ```

   `db:seed` **truncates every table** before loading the catalogue. Run it once
   on an empty database, never against live orders. Leave `SEED_DEMO_PASSWORD`
   unset here so the demo customers get a random password nobody knows.

## 2. Render (API)

1. Push the repository to GitHub.
2. In Render choose **New → Blueprint** and select the repository. Render reads
   `render.yaml` and creates the `aranya-api` web service (Docker, free plan).
3. Fill in the variables marked `sync: false`:

   | Variable              | Value                                                       |
   | --------------------- | ----------------------------------------------------------- |
   | `DATABASE_URL`        | The Neon pooled connection string                           |
   | `CORS_ORIGINS`        | `https://<your-project>.vercel.app` (comma-separate extras) |
   | `PUBLIC_APP_URL`      | `https://<your-project>.vercel.app` (used in reset links)   |
   | `SEED_ADMIN_EMAIL`    | The admin's email (only used when no admin exists)          |
   | `SEED_ADMIN_PASSWORD` | At least 12 characters; rotate after first sign-in          |

   `JWT_SECRET` is generated by Render. `RUN_MIGRATIONS=true` applies pending
   migrations on every boot, which is safe because Drizzle records what ran.

4. Deploy. The health check is `GET /api/health/ready`, which also pings the
   database. `GET /api/health` is the liveness probe and `/docs` serves the
   OpenAPI reference.

Free Render services sleep after inactivity. The web app warms the API on load
and shows "Waking up the server…" while it retries 502/503/504 for up to 90 s.

## 3. Vercel (web)

1. Import the repository in Vercel. Leave **Root Directory** as the repo root;
   `vercel.json` sets the install, build and output settings.
2. If your Render service is not called `aranya-api`, edit the `/api/:path*`
   destination in `vercel.json` to your service URL.
3. Optional: set `SITE_URL=https://<your-domain>` so `sitemap.xml` and
   `robots.txt` use your domain. Without it they use
   `https://aranya-ecommerce.vercel.app`. Also update the `og:image` and
   canonical URLs in `web/index.html` if you use a custom domain.
4. Deploy, then check:
   - `https://<app>/products/tulsi-elixir` loads on a hard refresh (SPA fallback).
   - `https://<app>/api/health/ready` returns `{"status":"ready","database":"up"}`.
   - Response headers include `Strict-Transport-Security` and `Content-Security-Policy`.

## Environment variables

Every server variable is validated at boot by `server/src/env.ts`; the process
exits with a clear message if one is missing or malformed.

| Variable                  | Where          | Default               | Purpose                                                                  |
| ------------------------- | -------------- | --------------------- | ------------------------------------------------------------------------ |
| `NODE_ENV`                | Render         | `development`         | `production` enables Secure cookies and HSTS on API responses            |
| `PORT`                    | Render         | `8787`                | HTTP port                                                                |
| `LOG_LEVEL`               | Render         | `info`                | pino level                                                               |
| `DATABASE_URL`            | Render         | (required)            | Postgres connection string                                               |
| `JWT_SECRET`              | Render         | (required, 32+ chars) | Signs access tokens; refused in production if it still says `replace-me` |
| `ACCESS_TOKEN_TTL`        | Render         | `900`                 | Access-token lifetime in seconds                                         |
| `REFRESH_TOKEN_TTL_DAYS`  | Render         | `30`                  | Refresh-token lifetime                                                   |
| `COOKIE_SAME_SITE`        | Render         | `lax`                 | Keep `lax` behind the Vercel proxy                                       |
| `COOKIE_DOMAIN`           | Render         | (unset)               | Only for sharing cookies across subdomains                               |
| `CORS_ORIGINS`            | Render         | (unset)               | Allowed browser origins; also enforced by the CSRF origin check          |
| `PUBLIC_APP_URL`          | Render         | (unset)               | Base URL for password-reset links                                        |
| `SEED_ADMIN_EMAIL`        | Render, seed   | (unset)               | Creates the first admin when none exists                                 |
| `SEED_ADMIN_PASSWORD`     | Render, seed   | (unset)               | Its password (12+ chars)                                                 |
| `SEED_DEMO_PASSWORD`      | seed (local)   | random                | Shared password for demo customers; leave unset in production            |
| `RUN_MIGRATIONS`          | Render         | `false`               | Apply migrations on boot                                                 |
| `PAYMENT_PROVIDER`        | Render         | `simulated`           | `simulated` or `razorpay`                                                |
| `RAZORPAY_KEY_ID`         | Render         | (unset)               | Razorpay **test-mode** key id, only with `PAYMENT_PROVIDER=razorpay`     |
| `RAZORPAY_KEY_SECRET`     | Render         | (unset)               | Razorpay test-mode secret                                                |
| `RAZORPAY_WEBHOOK_SECRET` | Render         | (unset)               | Verifies Razorpay webhook signatures                                     |
| `BODY_LIMIT_BYTES`        | Render         | `131072`              | Request body cap                                                         |
| `RATE_LIMIT_WINDOW_MS`    | Render         | `60000`               | Rate-limit window                                                        |
| `RATE_LIMIT_MAX`          | Render         | `30`                  | Requests per window for general routes                                   |
| `AUTH_RATE_LIMIT_MAX`     | Render         | `10`                  | Requests per window for login, register, forgot-password                 |
| `TRUST_PROXY_HOPS`        | Render         | `0`                   | Proxies that append to `X-Forwarded-For`; `2` behind Vercel + Render     |
| `MAIL_ADAPTER`            | Render         | `console`             | Reset emails are logged (links only outside production)                  |
| `SITE_URL`                | Vercel (build) | Vercel URL            | Absolute URLs in `sitemap.xml` and `robots.txt`                          |
| `VITE_API_URL`            | Vercel (build) | `/api`                | Only to bypass the proxy and call the API directly                       |

Local-only: `TEST_DATABASE_URL` (Vitest) and `E2E_DATABASE_URL` (Playwright).

## Rolling back

- **Web:** promote the previous deployment in the Vercel dashboard.
- **API:** redeploy the previous commit from the Render service's **Events** tab.
- **Database:** migrations are forward-only. Neon's branch-from-timestamp restore
  is the safety net; take a branch before applying a destructive migration.
